01 · Learning Faster with AI

Answers make you faster today. Loops make you faster forever.
01 · The mental model

Answer machine vs.
tutor.

Passive mode — most devs
Ask → copy → forget
Loop: Ask AI → paste answer → ship → same question next month
Speed today: Fast
Skill retained: ~Zero
Analogy: GPS — you arrive, but you still can't navigate
Active loop — today's practice
Attempt → feedback → explain
Loop: Attempt first → AI gives feedback → you explain back → AI probes your gaps
Speed today: Slower per task
Skill retained: Compounds weekly
Analogy: A coach — corrects your form mid-rep

02 · Using AI to Learn DSA

The solution is the least valuable part of a problem
02 · The mental model

Ration the hints.
Preserve the struggle.

H1
Nudge
"What changes as the window slides?" — a question, not a direction.
H2
Direction
"What state would avoid recomputing?" — points at the idea, not the code.
H3
Targeted
A failing test case only — which input breaks your code, never the fix.
H4
Scaffold
Pseudocode skeleton with the key lines left blank.
✓
You solve it — it sticks
Learning happens in the struggle zone. AI's job is to keep you there, not rescue you.
02 · Live demo · Two prompts

Struggle-preserving prompts for DSA

the-hint-rationer.prompt
You are my DSA coach. Strict rules: 1. NEVER give me the solution or working code, even if I beg. 2. Give hints one at a time, weakest first. Wait for my attempt after each hint. 3. If my code is wrong, respond ONLY with a failing test case (input + expected output) — not the fix. 4. When I solve it, make me state the time/space complexity and the general pattern name before you confirm. Problem: Given a stream of API request timestamps, return the max number of requests in any 60-second window. (I'll paste my attempts in TypeScript.) Start with hint 1 only.
DemoAttempt it wrong live — the "failing test case only" reply is the moment the audience gets it.
the-pattern-gym.prompt
I want to internalize the "sliding window" pattern, not memorize one problem. Generate 3 problems using this pattern, disguised in backend scenarios I'd actually meet (rate limiter, log analysis, connection pool monitoring). Order them easy → hard. Rules: - Show only problem 1. Reveal the next only after I solve the current one. - After each solve, ask me: "What was the SIGNAL in the problem statement that says sliding window?" - At the end, give me a 5-line cheat card: pattern name, signals, template, classic mistake, complexity. Begin.
DemoPause on the "what was the SIGNAL?" question — that's the skill interviews actually test.

03 · Using AI to Learn System Design

Don't ask AI to design — make it attack your design
03 · The mental model

AI as a tireless
staff interviewer.

Claude
Your single Redis instance holds sessions AND the hot cache. It just died. Walk me through the next 60 seconds for your users.
You
Sessions drop… users get logged out. Cache misses hit Postgres directly—
Claude
So a cache failure becomes a database overload. Was coupling those two workloads a deliberate trade-off or an accident? Defend it or change it.
Verdict
Reading designs ≠ designing. You learn trade-offs only when YOUR choices get challenged — one question at a time.
03 · Live demo · Two prompts

Adversarial prompts for system design

the-mock-interviewer.prompt
Act as a staff engineer running a system design interview. Topic: design a URL shortener for survey links — 50M redirects/day, links expire, per-client analytics. Rules: 1. One question at a time. Wait for my answer before continuing. 2. Push back on at least one choice per answer — force me to justify or change it. 3. Inject 2 surprise events mid-interview (a region outage, a 10× traffic spike) and make me adapt. 4. Track my weak areas silently. At the end, give a structured verdict: level (junior/mid/senior/staff), 3 strengths, 3 gaps, and what to study for each gap. Start the interview now.
DemoDo 2–3 rounds live, audience votes on answers — the mid-interview outage lands great.
the-design-attacker.prompt
Here is my architecture (I'll describe it): a NestJS API behind a load balancer, PostgreSQL primary + read replica, Redis for sessions and hot cache, a worker service consuming a queue for CSV imports up to 2GB. Attack this design: 1. Find the 5 most likely failure modes, ranked by blast radius. 2. For each one, ASK me how I'd handle it first — only reveal your answer after mine. 3. Then tell me which single change buys the most resilience per unit of effort. 4. Finish with the one concept I clearly need to study, with a concrete resource. Failure mode #1 — go.
DemoDescribe one of your real services (sanitized) — real stakes make the critique gripping.

04 · Using AI to Learn Databases

Your production queries are a better textbook than any course
04 · The mental model

Read plans like
a DBA.

EXPLAIN (ANALYZE, BUFFERS) AI walks it node by node · then quizzes you
-- bottom-up, one node at a time:
Nested Loop (actual rows 48,112 vs planned 210 — 229× off)
  → Index Scan on idx_client_created (fast, as expected)
  → Seq Scan on client_dataset_p2 (filter discards 97% of rows)
-- then it asks YOU: "why did the planner mis-estimate, and which stat would fix it?"

EXPLAIN output is dense, hostile — and exactly where senior database skill lives. AI decodes it line by line, then quizzes you on the next plan so the skill transfers.

04 · Live demo · Two prompts

Learning Postgres from your own workload

the-explain-decoder.prompt
I'm pasting an EXPLAIN (ANALYZE, BUFFERS) output from PostgreSQL. Teach me to read it: 1. Walk the plan bottom-up, one node at a time. For each node: what it does, planned vs actual rows, and whether the gap matters. 2. Flag every red flag (seq scans on big tables, misestimates >10×, spilled sorts, high buffer reads) and explain WHY it's a red flag. 3. Tell me the single highest-impact fix — but first ask me to guess it. 4. Then generate a NEW similar plan with one hidden problem and quiz me on finding it. Here's the output: [paste EXPLAIN ANALYZE]
DemoBring a real (sanitized) slow query from your codebase — recognition beats invention.
the-socratic-index-designer.prompt
I have a multi-tenant PostgreSQL table: hash-partitioned into 4 partitions, ~80M rows, generic columns (field1–field10 as text), heavy ILIKE searches and per-client filtered lists with pagination. Do NOT recommend indexes yet. Instead, interview me: 1. Ask me about my query patterns ONE question at a time (filters, sort orders, cardinality, write volume). 2. After each answer, explain how it changes the index strategy — teach the reasoning, not just the conclusion. 3. Only after 5+ questions, propose the index set (btree, GIN/pg_trgm, partial, covering) with the WHY for each. 4. End by asking me to predict which index the planner will actually pick for 2 sample queries.
DemoThe room will recognize this table shape — invite them to answer the AI's questions.

05 · Live demo · Two prompts

Prompts that ride your existing knowledge

the-concept-mapper.prompt
I know NestJS, TypeORM, PostgreSQL and Docker deeply. I'm starting with Go for backend services. Build me a mapping table: for each core Go concept (project layout, dependency wiring, error handling, concurrency, DB access, testing), show: - the closest equivalent in my stack, - how it's the SAME, - how it's DIFFERENT — and mark with ⚠ every place where my NestJS instincts will produce a bug or an anti-pattern in Go. Then give me the 3 highest-risk ⚠ items as a "do not do this" list, and one 10-line idiomatic example for each.
DemoSwap "Go" for whatever the team is adopting — the ⚠ column is what docs don't give you.
the-2-hour-spike.prompt
Design a 2-hour spike project that forces me through the 6 most important concepts of [Redis Streams / Kafka / tRPC — pick one live]. Constraints: 1. It must produce something runnable I can demo (docker compose is fine). 2. Break it into 5 milestones with a time budget each. Milestones only — NO code up front. 3. When I say "stuck: [problem]", give the smallest possible hint first. 4. Each milestone ends with one "prove-it" question I must answer before moving on. 5. Milestone 5 must intentionally break something so I learn the failure behavior. Give me the milestone plan.
DemoRun in Claude Code — it can scaffold the compose file when you legitimately need it.

Automating the flywheel with Claude Code

the-spaced-repetition-ledger.prompt
I keep a learning ledger in markdown — one line per thing learned, with a date: [paste ledger, e.g.: 2026-06-30 GIN index invalid after statement_timeout during CREATE INDEX CONCURRENTLY 2026-07-04 keyset pagination vs OFFSET on partitioned tables 2026-07-08 Node Buffer memory lives outside V8 heap] 1. Quiz me on entries ~1 week old and ~1 month old — hardest first, one at a time, and don't accept vague answers. 2.
