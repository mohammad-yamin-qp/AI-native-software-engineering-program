AI Workflows
for Engineers

Slash commands, skills, and hooks — the three primitives that turn one-off prompts into production-grade repeatable workflows.

The problem

Every engineer
prompts differently.

Same codebase. Different words. Different quality. Different output — every single time.

The model is consistent. The prompting isn't.

The fix

Encode the workflow.
Not the prompt.

Check it into Git. Share it with the team. Run it the same way, every time, by anyone.

Three primitives

Commands. Skills.
Hooks.

01
Slash Commands — .claude/commands/name.md
Markdown files that define a step-by-step workflow. Triggered manually: /debug, /review, /test. Verb-oriented — you invoke them when you have a specific task.
02
Skills — .claude/skills/name/SKILL.md
Standing knowledge. Claude reads and applies it automatically when relevant — your NestJS patterns, team conventions, domain vocabulary. No invocation needed.
03
Hooks — .claude/settings.json
Deterministic shell scripts that fire on Claude's lifecycle events (PreToolUse, PostToolUse, Stop). Enforce rules the model cannot bypass — run tests, block secrets, check coverage.
Where things live

One folder.
Git-tracked.

your-repo/
├── CLAUDE.md ← EQC rules, stack conventions, naming patterns
└── .claude/
    ├── settings.json ← hooks config (PreToolUse, PostToolUse, Stop)

Every engineer on the team gets identical workflows — no personal drift between teammates.

Five Repeatable Workflows

Debug · Refactor · Test · Docs · Review
Workflow 1 · /debug

Root cause it.
Fix it. Verify it.

You
/debug "TypeError: Cannot read properties of undefined (reading 'id') at survey.service.ts:87"
Claude
Reading survey.service.ts:87… owner is not eagerly loaded in TypeORM query.
Fix: add relations: ['owner'] to findOne. Applying…
Hook
PostToolUse → running: npm run test -- survey.service.spec.ts
Result
✓ 12 tests passed. Root cause: missing relation. Fixed in 1 edit.
Workflow 1 · debug.md anatomy

What the command file contains

.claude/commands/debug.md
---
description: Root-cause a bug, fix it, and verify with tests
allowed-tools: Bash, Read, Edit, Glob
argument-hint: [error message or stack trace]
---
 
## Steps
1. Parse $ARGUMENTS → extract file, line, error type
2. Read failing file + its imports
3. Identify root cause (not symptom)
4. Apply the minimal fix — one file at a time
5. npm run test -- --testPathPattern=<spec>
6. Iterate max 3 rounds if still failing
7. Report: root cause · fix · test result
Workflow 2 · /refactor

Plan first.
Then act.

You
/refactor src/survey/survey.service.ts
Claude
Issues found: fat service (14 methods, 3 concerns), magic strings ×6, no ISurveyCreateDto.

Plan: extract SurveyNotificationService, move constants, add interface.

Proceed? (yes / no)
You
yes
Claude
Step 1/3 done — SurveyNotificationService extracted. All existing tests pass. Continuing…

The plan gate is baked into the command. Claude will not edit a file until you approve.

Workflow 3 · /test

Generate. Run.
Cover.

You
/test src/translation/translation.service.ts
Claude
Found 4 public methods. Scanning existing specs for mock patterns… reusing HttpService mock from survey.service.spec.ts.

Generating 8 test cases: happy path, edge cases, error branches. Running coverage…
Result
Coverage: 94% branches. 1 uncovered: cacheResult() when Redis unavailable. Adding test…

Claude scans your existing spec files first — the generated tests look like your team's existing tests, not generic boilerplate.

Hooks — The Enforcement Layer

Rules the model cannot bypass
Hooks · settings.json

Deterministic.
Every time.

settings.json PostToolUse · PreToolUse · Stop
{
  "hooks": {
    "PostToolUse": [{ "matcher": "Edit",
      "hooks": [{ "type": "command", "command": "npm run test --silent" }] }],
    "PreToolUse": [{ "matcher": "Edit",
      "hooks": [{ "type": "command", "command": "detect-hardcoded-secrets.sh" }] }],
    "Stop": [{ "hooks": [{ "type": "agent",
      "prompt": "Check branch coverage >= 80%" }] }]
  }
}

Unlike prompts — hooks run regardless of what Claude decides. Shell exit code 0 = proceed. Non-zero = blocked.

Command vs. Skill

When to use which
The mental model

Verb vs.
Handbook.

Command
/debug, /review, /test
Trigger: You type /name
Best for: A task with a clear start — debug this error, review this branch
Scope: Narrow, time-boxed
Analogy: A runbook you open when needed
Skill
backend-nestjs-conventions
Trigger: Claude infers from context
Best for: Standing knowledge — team standards, patterns, domain vocabulary
Scope: Broad, persistent across the session
Analogy: A teammate who has absorbed your handbook
Which one? · Decision guide

Ask: is it a verb or a rule?
